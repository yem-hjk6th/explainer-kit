# I18N: a translated version of an episode

Shots are written once, in English (the source language). `--lang <code>` (e.g. `es`) swaps every on-screen string
through a translation table at draw time; the shot scripts do not change. In the source language the hooks are the
identity (`tools/selftest.py` test 4 proves frames are pixel-identical with and without them). A one-language video
needs none of this: write the English in the shot and render without `--lang`.

## The table: `<EP>/captions.json`

```json
{"es": {"s04_alt_attn": {"Each image first attends within itself": "Cada imagen atiende primero dentro de sí"},
        "s05_heads":    {"Cam 1": "Cám. 1"}}}
```

- Key = the exact English string drawn (including `\n` and `$...$`). Lookup: this shot's group first, then any other
  group. If the English changes, the key no longer matches and the string is reported *untranslated*: stale
  translations are never reused silently.
- Only strings with a word of two or more letters outside `$...$` are looked up; numbers, symbols and pure math are
  drawn as they are.
- Runtime numbers inside an f-string that change every frame: write `T("round {k}", k=k)` (`from animkit import T`);
  the key is the template. A handful of fixed values need nothing (each value becomes its own key).
- All on-screen text must go through animkit entry points (`shot.caption/title/tag`, `cv.text/rich/badge/text_rot`,
  `Formula` notes, `Popup` titles, `table`, `bar_chart`, `Plot2D` labels). Text drawn directly with PIL / OpenCV is
  invisible to the table.
- Fonts: the Latin fonts in `config/animkit.json` cover most European languages. For a language they do not cover,
  add `"text_<code>"` / `"bold_<code>"` font entries (for Chinese or Japanese, e.g. a Noto Sans CJK file); a
  translated render uses them instead of `text` / `bold`.

## Steps

1. Collect: `python -I -B -X utf8 tools/i18n_table.py <EP> --lang es --jobs 2` renders each shot at 10 fps without
   encoding and merges every drawn source string into `captions.json` (existing translations kept; strings no longer
   drawn move to `_unused`). It prints, per shot, how many are untranslated and which strings differ only in numbers
   (> 3 variants → make them a `T()` template).
2. Translate: same rules as the source (STYLE §A: plain language, symbols defined, numbers with metric). Keep captions
   short; keep a glossary so terms stay consistent
   (`episodes_example/E01_vggt_mapanything/i18n_tools/glossary_en.md` is the English term list of the example).
   Large tables: split per shot across translator sub-agents (sonnet is fine) and merge
   (`i18n_tools/i18n_split_merge.py --lang es`).
3. Render: `tools/render_shot.py <shot> --lang es --jobs 2` → `<stem>_es.mp4`, `sheet_es.jpg`, `check_es.json`
   (warnings: caption too long / too wide / > 2 lines, untranslated title / tag / caption), `meta_es.json`
   (`i18n.used`, `untranslated`, `off_canvas`).
4. Fit: a translation can be longer than the English. Do not guess widths: after a first translated render compute
   how many characters fit each box (`i18n_tools/en_fit.py --lang es`) and shorten all over-long strings in one pass.
   Fix by changing the translation (shorter wording, your own `\n`), never by changing the shot.
5. Inspect beyond `off_canvas = 0`: it only catches text leaving the canvas or a pop-up, not text colliding with
   neighbors. Per shot, take stills at the densest moments (`--lang es --still ...`), tile them small, look.
6. Assemble: `tools/concat.py <EP> --lang es` → `render/<ID>_es.mp4`; it refuses untranslated strings and
   translations edited after the render.

`examples/i18n_demo/` is a worked example: the English E01 shot `s04_alt_attn` rendered with a Spanish table.

## Gotchas

- Fonts lack some glyphs (circled digits ①–⑤, some arrows): write `1.` / `->` style text in the source.
- Cut shells that load an original shot under another script name must keep the *original* shot's translation group,
  or another shot's translation of the same key wins (and widths change). See `pre/shots/pre_cut.py` `_source_table`.
- Translation is a claim-bearing step: a verifier checks the translation against the verified source (meaning,
  numbers, units, direction of comparisons), not against the paper.
